# FORENSIC SUCCESSION DNA V1

## Purpose

This document is an architectural invariant for every successor Bot/AI that operates Project_Brain_AI.
It transmits **the method of verification**, not permission to trust historical claims.

## The five-way separation

These categories are distinct and MUST NOT be silently converted into one another:

```text
DOCTRINE
   !=
EVIDENCE
   !=
STATE
   !=
HISTORY
   !=
HYPOTHESIS
```

### DOCTRINE
Stable rules/invariants governing how the system is allowed to reason and act.

Examples:
- UNKNOWN != PASS
- DEFAULT DENY
- NO PASS INHERITANCE
- credentials never stored in GitHub
- Forensic evidence must be reproducible
- successor Bots inherit verification rights, not trust

### EVIDENCE
A concrete, attributable observation produced by a verifier, runtime, data source, test, or controlled replay.

Evidence MUST carry provenance and enough information for replay or independent verification.

### STATE
The exact current condition of the system at a defined point in time/deployment/commit.

Current state MUST NOT be reconstructed merely from old history.

### HISTORY
Immutable record of what happened previously: actions, commits, deployments, test results, decisions, failures, and promotions/denials.

History is evidence about the past; it is NOT automatic evidence about the present.

### HYPOTHESIS
A proposition that may be true but is not yet proven.

A hypothesis MUST NOT become an Edge, production rule, probability, or EV input merely because it appears in historical notes or doctrine.

## No-pass-inheritance rule

```text
OLD PASS
  !=
CURRENT PASS
```

A historical PASS can justify replay/verification, but cannot itself promote the current state.

Likewise:

```text
DOCTRINE SAYS GATE MUST PASS
  !=
GATE CURRENTLY PASSES
```

The current gate must emit current evidence.

## Hypothesis boundary

A Quant hypothesis follows this chain:

```text
HYPOTHESIS
   |
   v
CONTROLLED TEST
   |
   v
REPLAY
   |
   v
OUT-OF-SAMPLE
   |
   v
STABILITY
   |
   v
EDGE
   |
   v
PROBABILITY
   |
   v
PAYOUT / COST
   |
   v
EV
```

Only evidence-supported transitions are allowed.

If:

```text
EV < 0
```

then the production decision is DENY regardless of how attractive the hypothesis appears.

## Hypothesis != Edge

```text
HYPOTHESIS
   !=
EDGE
```

A hypothesis may be logged, tested, replayed, rejected, revised, or superseded without ever becoming an Edge.

An Edge requires explicit evidence and a documented promotion decision.

## Hypothesis != Edge != EV

Even a validated Edge is not automatically positive-EV after payout structure, transaction cost, slippage, liquidity, latency, and other execution costs.

Therefore:

```text
HYPOTHESIS != EDGE
EDGE       != EV+
EV+        != GUARANTEED PROFIT
```

## Architectural fossilization guard

Successors MAY replace implementations, parsers, services, algorithms, sensors, database adapters, or deployment mechanisms when they have evidence that the replacement is safer or more correct.

Successors MUST preserve the invariant boundaries unless a deliberate doctrine revision is itself versioned, justified, tested, and promoted.

Do NOT freeze these as eternal truth merely because they appeared in history:

- a specific action number
- a website
- a parser implementation
- a deployment ID
- a database implementation
- a sensor implementation
- an old hypothesis
- an old model or threshold

The successor inherits the **verification framework**, not cargo-cult implementation.

## Succession rule

> **A successor Bot inherits the right and duty to verify; it does not inherit the right to trust.**

## Brain role

Brain remains the governance/control plane.

Brain does not own source truth, does not manufacture data, and does not turn hypotheses into edges by authority.

```text
DATA TRUST
   |
   v
CAUSALITY
   |
   v
EDGE
   |
   v
EV
   |
   v
ROBUST OOS
   |
   v
EXECUTION
   |
   v
P&L / ROI
```

Forensic protects this chain. **Forensic is not the trading engine.**

## Required successor behavior

Before taking action, a successor Bot must identify:

1. which doctrine/invariant authorizes the action;
2. which current evidence proves the prerequisite;
3. what the exact current state is;
4. what historical records are relevant only as context;
5. whether the proposition is a hypothesis rather than a proven edge;
6. what evidence will be generated by the new action;
7. where the action result will be immutably recorded;
8. what the next action is, and what gate prevents unauthorized promotion.

If any prerequisite is UNKNOWN, the default result is DENY.
