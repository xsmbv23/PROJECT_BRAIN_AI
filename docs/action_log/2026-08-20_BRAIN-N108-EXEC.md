# BRAIN-N108-EXEC — Execution Bridge Implementation

## Decision

Option B is implemented as a **minimal forensic-compliant execution primitive**.

## Exact design

The bridge is not a new trust root. It is a fixed trigger only.

```text
Authorized caller
      |
      | X-Forensic-Probe-Token
      v
/forensic/run-transport-probe
      |
      | fixed command, no caller arguments
      v
python tools/transport_probe.py
      |
      v
raw stdout persisted verbatim
      |
      v
external verifier
```

## Hard boundaries

- No arbitrary command execution.
- No caller-controlled URL.
- No caller-controlled probe arguments.
- No receipt parsing by endpoint.
- No receipt returned in HTTP response.
- No fake receipt generation.
- No local curl substitution.
- No proxy execution.
- Probe semantics unchanged.
- `HTTP 202` means execution/persistence only, never forensic promotion.
- Missing authorization remains DENY.

## Current limitation

The bridge is implemented in source, but an exact-live execution is still not proven until the Render service has the authorization secret bound and an authorized execution invocation is observed in the exact deployment.

Therefore implementation completion is **not** runtime execution completion.

## Gate state

```text
BRIDGE_SOURCE_IMPLEMENTED = PASS
BRIDGE_SECURITY_CONTRACT = PASS
EXACT_LIVE_EXECUTION       = NOT_PROVEN
TRANSPORT_RECEIPT          = NOT_PROVEN
SOURCE_PROMOTION           = DENY
LAYER_1                     = ROOM_01_ONLY
STAIRCASE                   = LOCKED
```

## Successor instruction

The next Bot must not treat the existence of this endpoint as proof. It must verify the exact deployment, the secret binding, the fixed endpoint execution, the raw receipt, and the independent runtime-binding evidence.
