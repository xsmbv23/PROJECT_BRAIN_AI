# BRAIN-N079 — TLS Admission Regression Correction

## Trigger

Render runtime boot gate reported `DENY` because two existing tests expected the durable PostgreSQL adapter to silently upgrade an unsafe/missing `sslmode` to `sslmode=require`.

The adapter itself was already fail-closed: `_require_tls_database_url()` rejects missing or non-admitted TLS modes with `DATABASE_TLS_NOT_EXPLICIT`.

## Forensic assessment

The tests were stale relative to the invariant. Silently upgrading an unsafe credential binding would violate the admission-chain rule:

`PASS_IS_LOCAL_TO_GATE; PASS_IS_PREREQUISITE_ONLY; NO_PASS_INHERITANCE; UNKNOWN_IS_NOT_PASS; DEFAULT_DENY`

The correct behavior is **DENY**, not mutation of the connection string.

## Correction

Updated `tests/test_durable_postgres.py` so:

- PostgreSQL URL without explicit TLS => `DENY`
- `sslmode=disable` => `DENY`
- admitted `sslmode=require|verify-ca|verify-full` => accepted
- no test permits implicit TLS upgrading

## Important successor rule

Tests are evidence about the contract. They must not force the implementation to weaken a security invariant merely to make CI green.

If a test conflicts with a higher-order immutable Forensic rule, classify the test as stale, correct the test, and preserve the invariant.
