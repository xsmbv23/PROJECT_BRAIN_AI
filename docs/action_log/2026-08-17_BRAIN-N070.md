# BRAIN-N070 — Forensic Admission FSM Freeze

## Decision

N070 freezes the database admission model as **one ordered Forensic state machine**. These are not multiple independent forensic states.

```text
DB_EXISTENCE
  -> DB_BINDING
  -> SECRET_RESOLUTION
  -> DB_TLS_ADMISSION
  -> NETWORK_ORIGIN_PROOF
  -> DB_ROUND_TRIP
  -> PROMOTION
```

## Non-inheritance

```text
PASS(N) != PASS(N+1)
```

PASS is a prerequisite only. It never grants or implies a deeper PASS.

## Reachability

After the first FAIL or UNKNOWN, all downstream gates are `UNREACHED` for that evaluation. No ghost PASS, inferred FAIL, or fabricated downstream result is allowed.

## Historical immutability

A failed/unknown event is append-only and reason-coded. A later retry creates a new event and never erases the old event.

## Environment evidence

```text
LOCAL PASS != RENDER PASS
DOCUMENTED TARGET != EXECUTED PROOF
```

Production claims require the exact runtime anchor and exact-current deployment evidence.

## Runtime anchor

The runtime anchor remains unchanged. Documentation evolution must not overwrite the runtime identity.

## N071 additions

The next admission action explicitly requires two additional proofs before durable round-trip:

1. `SECRET_RESOLUTION` — prove the exact runtime received `DATABASE_URL` through the approved Render Secret Environment boundary, without exposing the secret.
2. `NETWORK_ORIGIN_PROOF` — prove the final DB interaction is attributable to the exact Render runtime; local/tunnel/cache/proxy ambiguity is not accepted.

These are additions to the existing ordered FSM, not a new forensic system and not an excuse to create an infinite infrastructure loop.
