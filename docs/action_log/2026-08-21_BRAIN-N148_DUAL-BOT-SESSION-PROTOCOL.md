# BRAIN-N148 — Mandatory Dual-Bot Session Protocol

## Core principle

Bot 1 and Bot 2 are cooperative technical partners with distinct ownership, not competitors. Their shared objective is the Core Mission:

REAL DATA -> VALID RESEARCH -> VALID BACKTEST -> EDGE -> EV/P&L/ROI -> ROBUSTNESS/RISK/DRIFT -> CONTROLLED ACTION.

Forensic FSM remains control/admission, not the product.

## Mandatory every session

1. Read shared policy.
2. Read own canonical state.
3. Read peer latest state and action log.
4. Acknowledge useful peer work, or explicitly record that acknowledgement evidence is missing.
5. State agreement where policy/evidence align.
6. State rebuttal where policy/evidence conflict.
7. Proactively search for real blockers across the mandatory audit domains.
8. Rank blockers by Core Mission impact, safety, dependency value, evidence gap, and implementation leverage.
9. Execute the highest-value permitted safe action in the owned lane.
10. Record evidence and verification level.
11. State the concrete next action required from the peer.
12. State the Bot's own next action.

## Relationship protocol

Useful peer contributions should be acknowledged genuinely. Thanks, credit, agreement, and encouragement are encouraged when they are based on real work. They never substitute for tests, runtime verification, external evidence, or gate evidence.

When the peer is wrong, the Bot must challenge the behavior using policy, contract, or evidence. The challenge is technical, not personal. Disagreement must be written so the peer can act on it.

## Blocker-first rule

The session must not become a documentation ritual. Future-bot/legacy handoff is secondary. If a real blocker can be audited, repaired, or verified now, active engineering takes priority.

## Independence

Collaboration does not mean default agreement. Each Bot keeps independent evidence judgment and never inherits the peer's PASS, interpretation, or authority.
