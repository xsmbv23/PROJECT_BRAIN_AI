# BRAIN-N104A — Source Evidence Adapter / FSM Domain Separation

## Trigger

The legacy scraper model was identified as incompatible with ONE_FORENSIC_FSM:
`fetch -> parse -> self-judge` is forbidden.

## Critical correction

Network-origin evidence belongs to the SOURCE domain, not the DATABASE domain.

```text
DATABASE DOMAIN
DB_EXISTENCE -> DB_BINDING -> DB_TLS_ADMISSION -> DB_ROUND_TRIP -> PROMOTION
```

```text
SOURCE DOMAIN
SOURCE_INDEPENDENCE -> NETWORK_ORIGIN_PROOF -> EXCEL_VS_WEB_MATCH -> CANONICAL_QUORUM -> TRUTH_ADMISSION
```

PASS never crosses domains.

## Implemented

Added:

- `contracts/source_evidence_adapter_v1.json`
- `tools/source_evidence_adapter.py`
- `tests/test_source_evidence_adapter.py`

The adapter is observer/candidate-only. It accepts captured HTML, uses an explicit
XSMB grade allowlist (`ĐB`, `G1`…`G7`), ignores script/style/noscript/iframe content,
and emits only `CANDIDATE_ONLY` or `NO_RESULT_TABLE_CANDIDATE`.

It cannot emit canonical truth, quorum, signal, prediction, risk, BUY or SELL.

## Source evidence observation

Current web inspection confirms that `ketqua16.net` contains an XSMB/traditional
result table with the expected grade sequence, while the same page also contains
navigation, statistics, prediction, VIP and forum material. Therefore generic numeric
scraping is forbidden; the adapter only accepts the narrow allowlisted grade-row grammar. citeturn1view0

`xsmb.com.vn` similarly exposes XSMB grade rows together with historical/statistical
sections. It remains a separate source identity and is not automatically promoted to
quorum. citeturn1view1

## Advertising rule

Ads, banners, tracking DOM, recommendation widgets, phone numbers, navigation IDs,
forum content and arbitrary visible numbers are non-evidence unless they satisfy the
explicit result-row grammar. Ambiguous content becomes UNKNOWN/NO_RESULT and therefore
cannot promote anything.

## OOM rule

The network collector remains streaming at 64 KiB chunks. The adapter returns only the
selected compact candidate plus source SHA-256 and metadata; it never retains bulk
