# BRAIN-N091A — Forensic Correction: State Drift vs Code-Version Drift

## Why this correction exists

N091 established the single Brain state authority chain. During implementation, one subtle problem was identified before it could become an architectural error:

**Do not require `current_state.json` commit SHA == currently deployed commit SHA.**

That rule creates a self-referential deployment loop because changing `current_state.json` creates a new commit, which changes the deployed commit, which would make the state stale again.

## Correct model

```text
LOGICAL STATE AUTHORITY
    = Brain current_state.json

RUNTIME COMMIT SHA
    = immutable code-version evidence

DEPLOYMENT ID
    = supplemental operational evidence

AUTHORITY PROTOCOL VERSION
    = compatibility gate

STATE SCHEMA VERSION
    = compatibility gate
```

Therefore:

```text
runtime commit differs from last verified commit
            !=
logical state was externally mutated
```

It means:

```text
CODE VERSION DRIFT
        ↓
RECONCILIATION REQUIRED
```

not an automatic claim of logical-state corruption.

## Hard deny conditions

Only these are immediate authority failures:

```text
unknown authority repository
unknown authority path
incompatible authority protocol
incompatible state schema
unknown required rule
```

A new runtime commit with the same compatible authority protocol is:

```text
RECONCILE_REQUIRED
```

until exact-current runtime evidence is re-attested.

## Preserved invariants

```text
BRAIN = ONLY LOGICAL STATE AUTHORITY
QUANT = READ-ONLY PROJECTION
DATA = READ-ONLY PROJECTION
RUNTIME = EVIDENCE
HISTORY = IMMUTABLE HISTORY
PASS = LOCAL TO GATE
NO PASS INHERITANCE
UNKNOWN != PASS
DEFAULT DENY
```

## Result

This correction prevents the State Authority Chain itself from becoming a source of false positives or endless deployment loops.

`BRAIN-N092` must integrate reconciliation at the admission boundary using **protocol/schema compatibility + explicit runtime evidence**, not self-referential commit equality.
