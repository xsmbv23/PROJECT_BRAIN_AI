# BRAIN-N036 — Passive Corridor Warning Sensor

## Architectural addition

Added a passive corridor sensor modeled as a motion-triggered hallway light.

When an actor approaches a corridor, the sensor may:

1. illuminate the corridor;
2. emit a security telemetry event;
3. classify the approach as INFO or WARNING.

It **cannot** unlock a room, issue a capability, bypass a key, or authorize a layer transition.

## Separation of concerns

```text
                 APPROACH
                    │
                    ▼
             Corridor Sensor
                    │
          ┌─────────┴─────────┐
          ▼                   ▼
     LIGHT = ON           SECURITY EVENT
          │                   │
          └─────────┬─────────┘
                    ▼
               OBSERVATION
                    │
                    X
              NO AUTHORITY

Only this path grants access:

Capability + Key + Corridor + Layer Edge
                    ↓
                authorize
```

## Why this belongs in the foundation

Security should be observable before it becomes an authorization decision. A corridor can warn that something is approaching without confusing detection with permission.

This creates a future-safe place for additional passive sensors: motion, anomaly, rate-limit, repeated-denial, corridor tamper, or unusual traversal patterns.

## Safety invariant

`SENSOR_SIGNAL != ACCESS_CAPABILITY`

A warning light must never become a master key by accident.
