## Canonical decision — ONE Forensic FSM

The database admission model is **ONE Forensic FSM**, not multiple independent forensic systems.

There is one state machine and one evidence ledger. The apparent “multiple forensic states” are local gate results inside the same admission chain.

Sequential gates:

```text
DB_EXISTENCE
   -> DB_BINDING
   -> SECRET_RESOLUTION
   -> DB_TLS_ADMISSION
   -> NETWORK_ORIGIN_PROOF
   -> DB_ROUND_TRIP
   -> PROMOTION
```

### Non-inheritance law

```text
PASS(G_n)  !=>  PASS(G_n+1)
```

A PASS is local evidence for its own gate only. It never becomes authority for the next gate by inheritance or inference.

```text
DB_EXISTS = PASS
    !=> DB_BINDING = PASS

DB_BINDING = PASS
    !=> SECRET_RESOLUTION = PASS

DB_TLS_ADMISSION = PASS
    !=> DB_ROUND_TRIP = PASS

DB_ROUND_TRIP = PASS
    => only then may PROMOTION be considered,
       subject to all other gates being PASS.
```

## Edge tracing law

Every state transition is an explicit, auditable edge.

An edge must contain:

- source gate/state;
- target gate/state;
- observable evidence/receipt;
- decision result.

Therefore:

```text
missing source        -> DENY
missing target        -> DENY
missing evidence      -> DENY
unknown edge          -> DENY
broken edge           -> DENY
cross-layer edge with no contract -> DENY
```

No successor Bot may “jump” from a PASS state to another state merely because the transition looks logically convenient.

## EV<0 law

Expected Value belongs to the calculation layer, not Brain:

```text
DATA
  -> QUANT_ENGINE calculates EV
  -> explicit EV evidence
  -> BRAIN admission gate
  -> downstream execution only after admission
```

Brain does **not** invent, estimate, repair, clamp, or recompute EV for admission.

The admission rule is:

```text
EV < 0       -> DENY_ACTION
EV unknown   -> DENY_ACTION
EV NaN       -> DENY_ACTION
EV +Inf      -> DENY_ACTION
EV -Inf      -> DENY_ACTION
EV = 0       -> EV gate does not deny
EV > 0       -> EV gate does not deny
```

Important: `EV >= 0` is **not** a global PASS. It only means the EV gate itself has not denied. All other Forensic gates still apply.

A negative EV is therefore a **hard local denial edge**, and cannot be overridden by another sensor, confidence score, model output, or execution convenience.

## External trigger rule

For transitions requiring a real external event, Brain/Bot/chat cannot fabricate the event or evidence. Admissible GitHub workflow origins are:

- real manual workflow dispatch;
- real source push/commit event;
- real authorized external API dispatch.

Fresh runner execution identity and receipt must be observable before the FSM may consume the evidence.

`WAIT_EXTERNAL_EVENT` is valid and must not be converted to PASS by inference.

### Retry law

```text
RETRY = NEW FORENSIC EVENT
```

A retry may append a new receipt/event but may never overwrite, delete, or mutate historical receipts.

## Protected-room analogy

```text
corridor key -> room key -> inner latch -> doorbell/external event -> admission
```

Correct keys do not manufacture the inner release.

The analogy is a security model, not an assertion that the runtime has physical rooms or keys.
