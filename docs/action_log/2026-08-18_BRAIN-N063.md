## Key decision

The database admission model is ONE Forensic FSM, not multiple independent forensic systems.

Sequential gates:

```text
DB_EXISTENCE -> DB_BINDING -> SECRET_RESOLUTION -> DB_TLS_ADMISSION
-> NETWORK_ORIGIN_PROOF -> DB_ROUND_TRIP -> PROMOTION
```

A PASS is local evidence for its own gate only. It never inherits forward as authority.

## External trigger rule

For transitions requiring a real external event, Brain/Bot/chat cannot fabricate the event or evidence. Admissible GitHub workflow origins are:

- real manual workflow dispatch;
- real source push/commit event;
- real authorized external API dispatch.

Fresh runner execution identity and receipt must be observable before the FSM may consume the evidence.

`WAIT_EXTERNAL_EVENT` is valid and must not be converted to PASS by inference.

## Protected-room analogy

```text
corridor key -> room key -> inner latch -> doorbell/external event -> admission
```

Correct keys do not manufacture the inner release.

## Immutable successor obligations

Every future Bot must read the architecture contract plus current/next state before acting. It must append an action result before handoff and preserve all prior DENY/UNKNOWN events. A retry may add a new event but may not erase history.

## Anti-duplication

Brain remains Governance Control Plane. Quant Engine remains execution/calculation layer. Quant Engine rooms are function boundaries and must not recreate Brain's security/forensic authority.
