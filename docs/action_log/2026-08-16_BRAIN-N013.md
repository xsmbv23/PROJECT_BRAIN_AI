# BRAIN-N013 — Deployed Bounded Runtime Gate

## Action

The bounded verifier is now wired into the existing `xsmb-quant` Render service startup path behind an explicit foundation flag compiled into the Docker image.

## Runtime topology

```text
Render Free 512MB / 1 CPU
        |
        v
foundation_gate.py
        |
        +--> security selftest
        |
        +--> ONE real-source fixture
                |
                v
        render_safe_runner
                |
                +--> canonical_bounded_fixture
                |
                +--> compact runtime evidence
        |
        v
HTTP foundation service
```

## Guard

- hard platform boundary: 512 MB
- conservative execution guard: 320 MB
- one fixture only
- no historical concatenation
- no multiprocessing
- promotion remains DENY

## Deployment

Commit `d3df3afc31f05bee6770fc5ac4b68af00aa224f0` triggered a new Render deployment for `xsmb-quant`.
At recording time the deployment is `update_in_progress`; therefore this action **does not claim runtime PASS yet**.

## Why this is important

Earlier runtime logs proved the service could remain live with the security self-test, but the bounded fixture was not actually enabled. This action closes that gap by making the bounded test part of startup while keeping the workload bounded.

## Failure behavior

If the runner exits unsuccessfully or the 320 MB guard is breached:

```text
DENY
  |
  +--> compact evidence
  +--> no promotion
  +--> route future heavy work to external/build plane
```

A Render restart/OOM must never mutate canonical source truth.
