# BRAIN-N064 — Exact-Current Runtime Verification

## Objective
Verify that the deployed Render runtime is the exact current GitHub state, then observe the database admission chain without inference.

## Finding: deployment drift detected and corrected

At the start of N064, GitHub `main` had advanced beyond the live Render deployment. Render was still serving commit `4b5a9396aadf9d2cd8ca0c069c013c96fe01c762` while GitHub `main` had advanced to `08f17233261b1f3e0876e1c2515ee753d26180ea`.

This is a **Forensic deployment-drift condition**. It was not treated as harmless.

Action taken: manually triggered a Render deployment of the exact GitHub `main` commit.

## Important semantic clarification

The foundation test field `durable_round_trip=PASS` is a **foundation/unit verification result**. It is NOT evidence of a live PostgreSQL durable-evidence round-trip.

Only the dedicated database admission chain can promote durable DB capability.

This distinction is mandatory for successor Bots.
