# BRAIN-N076 — Cross-Region TLS / Network Origin Admission Boundary

## External operator observation

Current Render topology:

- `project-brain-ai`: Oregon, Free, 1 instance
- `xsmb-runtime-db`: Singapore, PostgreSQL 18, Free, available

This is a real cross-region boundary.

## Forensic interpretation

Cross-region is **not automatically a failure**. It is a topology fact that must be made explicit in the admission chain.

Therefore the correct state is:

```text
DB_EXISTENCE       = PASS
DB_BINDING         = BOUND (latest external runtime evidence)
SECRET_RESOLUTION  = NOT_PROVEN
DB_TLS_ADMISSION   = DENY_TLS
NETWORK_ORIGIN     = WARN / CROSS_REGION
DB_ROUND_TRIP      = NOT_PROVEN
PROMOTION          = HARD DENY
```

The latest exact state in `state/current_state.json` records the same semantics and requires fresh evidence at every gate.

## TLS invariant

`tools/durable_postgres.py` already fails closed unless the runtime `DATABASE_URL` explicitly declares one of:

- `sslmode=require`
- `sslmode=verify-ca`
- `sslmode=verify-full`

It does **not** auto-upgrade an unsafe URL.

Thus the operator request to append `?sslmode=require` is semantically correct, but the repository/runtime cannot safely manufacture or rewrite the secret because the current control surface does not expose the secret value.

No credential was fabricated, read back into the model, printed, or stored in GitHub.

## Action actually taken

Added:

```text
contracts/network_origin_proof_v1.json
```

This turns region drift into an explicit forensic contract rather than an undocumented assumption.

## Infrastructure decision

Do **not** silently recreate or replace the production Brain service merely to co-locate regions. Render's current mutation surface does not provide an in-place region migration for this service, and replacement would create a new service identity and potentially break the established admission path.

A future region migration must be an explicit infrastructure transition with:

1. new service admission contract,
2. environment/secret rebinding,
3. exact-current runtime replay,
4. OOM measurement,
5. network-origin evidence,
6. rollback/cutover evidence,
7. only then promotion.
