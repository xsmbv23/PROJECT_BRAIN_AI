## Forensic interpretation

Cross-region is **not automatically a failure**. It is a topology fact that must be explicit in the admission chain.

The current chain is:

```text
DB_EXISTENCE
    ↓
DB_BINDING
    ↓
SECRET_RESOLUTION
    ↓
DB_TLS_ADMISSION
    ↓
NETWORK_ORIGIN_PROOF
    ↓
DB_ROUND_TRIP
    ↓
PROMOTION
```

Each gate requires fresh evidence.

A PASS at one gate is only a prerequisite for the next gate. It never inherits permission downstream.

## TLS invariant

`tools/durable_postgres.py` fails closed unless the runtime `DATABASE_URL` explicitly declares one of:

- `sslmode=require`
- `sslmode=verify-ca`
- `sslmode=verify-full`

It does **not** auto-upgrade an unsafe URL.

The operator request to append `?sslmode=require` is therefore semantically correct.

However, the available Render control surface does not expose the current secret value, and the safe mutation interface cannot reconstruct the existing URL without risking credential loss or fabrication. Therefore the assistant must **not** overwrite `DATABASE_URL` with a guessed or partial value.

No credential was fabricated, read into repository state, printed, or stored in GitHub.

## Infrastructure decision

Do **not** silently recreate or replace the production Brain service merely to co-locate regions. The available Render mutation surface does not provide an in-place region migration for this service, and replacement would create a new service identity and potentially break the established admission path.

A future region migration must be an explicit infrastructure transition with:

1. new service admission contract,
2. environment/secret rebinding,
3. exact-current runtime replay,
4. OOM measurement,
5. network-origin evidence,
6. rollback/cutover evidence,
7. only then promotion.
