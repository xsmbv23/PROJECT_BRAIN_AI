# BRAIN-N007 — Render 512MB OOM Protection

## Decision

Render Free 512 MB / 1 CPU is a hard architectural boundary.

The system must classify workload before loading data and route heavy work away from Brain/UI.

## New governance artifact

`docs/RENDER_512MB_OOM_POLICY_V1.md`

It defines P0/P1/P2 workloads, routing, anti-OOM decision tree, memory safety rules and failure policy.

## Layer 1 artifact

`Quant_Engine/docs/ROOM_RESOURCE_BUDGET_V1.md`

Every future intelligence room must declare a resource budget before its door can open.

## Architecture consequence

```text
CHAT
  ↓
BRAIN / UI
  ├── P0 lightweight
  └── P1 bounded

DATA/BUILD PLANE
  └── P2 heavy

QUANT ENGINE
  ├── R0/R1 bounded rooms
  └── R2/R3/R4 external workers
```

A new repository/execution boundary may be introduced whenever it prevents unsafe memory pressure, but repository separation alone is not considered execution isolation.

## Fosennic protection

OOM/reset must never trigger silent data mutation, history rewrite, manifest rebuild, or promotion.

On failure, state remains resumable and promotion remains DENY.

## Current governance

```text
Brain foundation        = active
OOM policy              = LOCKED IN
Quant Engine             = room model only
Layer 1                  = LOCKED
Promotion                = DENY
```

## Next action

Continue foundation verification. Before any large XSMB execution, design the shard/worker boundary and verify bounded evidence flow. Do not run multi-year data workloads inside Render Free Brain/UI.
