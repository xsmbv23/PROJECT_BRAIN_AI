# BRAIN-N060 — TLS Durable Evidence Adapter + Scanner Boundary Repair

## Implementation

Added `tools/durable_postgres.py` as a minimal metadata-only durable evidence sink. The adapter is intentionally outside `core/` so the Brain governance/control plane remains dependency-isolated.

Security properties:

- runtime `DATABASE_URL` only;
- PostgreSQL scheme required;
- TLS explicitly required (`require`, `verify-ca`, `verify-full` accepted);
- non-PostgreSQL schemes denied;
- credential-shaped evidence fields denied;
- canonical SHA-256 envelope hashing;
- compact JSONB only;
- read-back hash verification;
- connection/write/read failures fail closed;
- no source datasets are loaded.

## Runtime failure discovered and repaired

The first Render deployment of N060 built successfully but the boot gate denied because the existing source scanner recursively inspected the installed `.venv` dependency tree. The binary `libpq` shared library shipped by `psycopg-binary` contained a credential-like string and was incorrectly treated as project source.

This was a **scanner-boundary defect**, not evidence that the dependency itself was a source credential leak.

Repair:

- source scan now excludes runtime artifact directories: `.venv`, `venv`, `__pycache__`, `.pytest_cache`;
- source scan ignores binary/archive suffixes: `.so`, `.dylib`, `.dll`, `.whl`, plus existing image/zip/pyc exclusions;
- unreadable/non-text files are skipped rather than interpreted as source text;
- `core/` adapter-import scan remains strict, so `psycopg` cannot enter the Brain core.

The original verifier semantics were restored in full after the boundary repair; no security test was removed to make the gate green.
