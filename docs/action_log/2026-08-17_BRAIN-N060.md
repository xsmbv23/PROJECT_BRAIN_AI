# BRAIN-N060 — TLS Durable Evidence Adapter

## Implementation

Added `core/durable_postgres.py` as a minimal metadata-only durable evidence sink.

Security properties:

- `DATABASE_URL` is read from runtime environment only unless explicitly injected by a caller.
- PostgreSQL scheme is mandatory.
- `sslmode` is normalized to `require` when absent or weaker; `verify-ca` and `verify-full` are preserved.
- non-PostgreSQL schemes are denied.
- credential-shaped envelope fields are denied.
- evidence is canonicalized and SHA-256 hashed before write.
- only a compact JSONB envelope is stored.
- read-back verifies both stored hash and recomputed hash.
- all driver/connect/write/read failures become explicit fail-closed `DurableEvidenceDeny` errors.
- the adapter never loads source datasets.

## OOM boundary

The adapter handles one compact envelope per call. It does not import pandas, read spreadsheets, load FULL_27, derive TAIL_27, or hold historical datasets.

## CI gate

`.github/workflows/foundation.yml` now installs only the bounded `psycopg[binary]` dependency and runs the durable adapter's standard-library unit tests before the foundation security verifiers. This is a bounded dependency, not a data-processing dependency.

## Runtime status

The implementation is now on `main` and should enter the normal Render auto-deploy path. A real database round-trip is not declared PASS until the deployed process proves it against the Render Postgres instance with TLS.
