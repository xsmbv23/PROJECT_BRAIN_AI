# BRAIN-N060 — Durable Evidence TLS Integration Gate

## Finding

The Render Postgres resource is AVAILABLE, but the Render SQL connector returned `FATAL: SSL/TLS required`. This is a transport/configuration boundary, not permission to weaken TLS.

## Required design

The durable evidence adapter must:

- accept `DATABASE_URL` only from runtime environment;
- require TLS explicitly;
- refuse plaintext PostgreSQL connections;
- keep credentials out of source, state files and action logs;
- write compact metadata envelopes only;
- never become the canonical XSMB data source;
- remain optional to the dataset-free Brain verification path;
- fail closed when the durable sink is configured but cannot establish verified TLS.

## OOM rule

The adapter is an evidence sidecar/boundary, not part of bulk data processing. It must not load FULL_27, TAIL_27, spreadsheets or historical datasets.

## Governance

Until a real TLS database round-trip is proven:

```text
DURABLE EVIDENCE = UNKNOWN
PROMOTION = DENY
LAYER 1 = LOCKED
STAIRCASE = LOCKED
```

## State synchronization rule

The action ledger and current state must be changed atomically whenever possible. A successor Bot must reject contradictory state pointers.
