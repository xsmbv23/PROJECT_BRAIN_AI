# BRAIN-N051 — Runtime Evidence via Render Boot Gate

## Finding

N049/N050 could not obtain execution evidence through the agent container or observable GitHub Actions runs. Render, however, is connected to `xsmbv23/PROJECT_BRAIN_AI` and can execute the repository on the real Free runtime.

## Corrective architecture

Added `tools/runtime_boot_gate.py` and wired it into `brain_server.py`.

Before the Brain HTTP server binds its port, the runtime now executes three lightweight, subprocess-isolated checks:

```text
state consistency
      ↓
foundation verifier
      ↓
protected-room access verifier
      ↓
Brain HTTP server
```

Any non-zero verifier exit prevents the Brain server from starting.

## Safety

- stdlib-only verifier path;
- no FULL_27 / TAIL_27 loading;
- no database/network access required by the verifier;
- subprocess isolation limits memory contamination of the long-lived Brain process;
- Render remains 1 CPU / 512 MB hard boundary;
- 320 MiB remains the conservative verifier memory guard.

## Evidence semantics

Render deployment of the exact Git commit is now the runtime execution evidence path. The boot gate prints a compact JSON envelope containing commit SHA, elapsed time, exit codes and output tails.

The gate is not yet declared PASS until the deployment completes and the logs show `runtime_boot_gate=PASS` for the exact commit.
