# BRAIN-N065 — KETQUA16 Source Evidence Adapter

## Purpose

Implement the first source adapter for `ketqua16.net` while preserving the split between the SOURCE DOMAIN and DATABASE DOMAIN.

## Architecture lock

```text
DATABASE DOMAIN
DB_EXISTENCE -> DB_BINDING -> DB_TLS_ADMISSION -> DB_ROUND_TRIP -> PROMOTION

SOURCE DOMAIN
SOURCE_INDEPENDENCE -> NETWORK_ORIGIN_PROOF -> EXCEL_VS_WEB_MATCH -> CANONICAL_QUORUM -> TRUTH_ADMISSION
```

There is no edge from a DB gate into a Source gate and no edge from a Source gate into a DB gate.

`PASS` is local to its gate. It is only a prerequisite for that gate's next local transition. PASS inheritance across domains is forbidden.

### Network evidence

The adapter performs a bounded HTTPS fetch directly against `https://ketqua16.net` and records only compact metadata:

- resolved IPs
- TLS protocol
- peer certificate SHA-256
- HTTP status
- content type
- bounded payload byte count
- payload SHA-256
- truncation flag

Payload reads are bounded in 64 KiB chunks and capped at 8 MiB to protect the Render 512 MB boundary.

No credential, cookie, token, or raw bulk payload is written to the evidence receipt.

### Candidate extraction

Candidate extraction is disabled unless an explicit selector allowlist is supplied through `KETQUA16_SELECTORS_JSON`.

The adapter therefore cannot guess selectors and cannot silently scrape advertisements or unrelated DOM regions.

The visible `ketqua16.net` page contains many non-truth regions (navigation, statistics, prediction/soi-cau, news, forum and advertising-related content). These are explicitly classified as non-truth content and are never accepted by the adapter as canonical evidence merely because they contain lottery-looking numbers. citeturn0view0

### Authority invariant

The adapter emits:

```text
EvidenceReceipt
CandidateRecord
```

It does NOT emit:

```text
PASS
PROMOTE
TRUTH
CANONICAL
MATCH
```

Content reconciliation belongs exclusively to `EXCEL_VS_WEB_MATCH`.
