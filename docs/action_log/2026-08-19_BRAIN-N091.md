# BRAIN-N091 — State Authority Chain / Reconciliation Layer

## Trigger

A review identified a new risk after the system entered reality: drift between Brain logical state, Quant projection state, data-plane state, Render runtime evidence, and historical action logs.

## Decision

The risk is real, but the latest exact-current state was re-read before changing anything.

Current Brain state already records:

- `DATA_ADMISSION_RUNTIME_VERIFIED`
- `DB_BINDING_BOUND_TLS`
- `NETWORK_ORIGIN_PROOF_PASS`
- `DB_ROUND_TRIP_PASS`

- `ROOM_01_DATA_ADMISSION`
- `ROOM_02` remains outside the admitted boundary
- `next_action_id = BRAIN-N091_RESEARCH_ADMISSION_PRECHECK`

Exact-current Render runtime was also rechecked:

```text

live_commit = 7d111f428a0d2e92856597b93b0502e674f37fda
```

The Brain state already records the same verified runtime commit `7d111f428a0d2e92856597b93b0502e674f37fda`.

Therefore the previously suspected Brain-vs-Render commit drift is **not present in the exact-current evidence**.

## Important refinement

Render deployment IDs are **not** used as immutable runtime identity. A redeploy can legitimately produce a new deployment ID while executing the same commit.

The immutable runtime identity for reconciliation is the deployed commit SHA.

Deployment IDs remain supplemental forensic evidence.

## State model

```text
Brain current_state.json
        │
        ├── logical state authority
        │
        ├── Quant Engine = READ-ONLY PROJECTION
        ├── xsmb-quant = DATA-PLANE PROJECTION
        └── Render runtime = EVIDENCE

EVIDENCE -> STATE -> ACTION
```

No downstream layer can promote or override Brain state.
