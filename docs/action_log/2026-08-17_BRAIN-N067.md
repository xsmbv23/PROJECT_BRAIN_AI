# BRAIN-N067 — Forensic Database Admission Chain Semantics

## Purpose

Preserve a critical architectural rule for all successor Bots.

The database states are **not two independent Forensic systems**. They are gates in **one ordered Forensic Database Admission Chain**.

```text
DB_EXISTENCE
    -> DB_BINDING
    -> DB_TLS_ADMISSION
    -> DB_ROUND_TRIP
    -> PROMOTION
```

## Immutable semantics

PASS at an earlier gate is **only a prerequisite to evaluate the next gate**.

PASS is never inherited.
PASS never grants a deeper capability.
Silence is never PASS.
UNKNOWN is never PASS.

Therefore:

```text
DB_EXISTS = PASS
    DOES NOT IMPLY
DB_BOUND = PASS
```

```text
DB_BOUND = PASS
    DOES NOT IMPLY
DB_TLS_ADMITTED = PASS
```

```text
DB_TLS_ADMITTED = PASS
    DOES NOT IMPLY
DB_ROUND_TRIP = PASS
```

Only:

```text
real compact metadata WRITE
    -> real READ
    -> SHA-256 MATCH
```

can satisfy the durable evidence gate.

## Security interpretation

Treat the database as a secured room:

1. Existence gate proves the room exists.
2. Binding gate proves the service has the room's key/binding.
3. TLS gate proves the key is being used under an accepted secure transport policy.
4. Round-trip gate proves the actor actually entered and can perform the permitted evidence operation.
5. Promotion gate grants the resulting capability.

A key for one gate is never a key for another gate.

## Successor rule

Never collapse the chain into one boolean such as `DATABASE_PASS`.

Never infer access from database existence.
Never infer TLS from binding existence.
Never infer write/read capability from TLS admission.
Never infer durable evidence integrity without an observed hash match.

The chain must remain explicit in machine-readable state and verifier output.
