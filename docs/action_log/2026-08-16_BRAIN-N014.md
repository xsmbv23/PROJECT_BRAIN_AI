# BRAIN-N014 — Persistent Runtime Evidence Boundary

## Action

Advanced the foundation from deployment-only verification toward durable runtime evidence.

## Problem closed

A Render filesystem artifact is not sufficient as the long-term source of truth because service instances can be replaced. Runtime evidence must therefore be compact, hash-addressed, and persisted through the foundation evidence path rather than depending on a local container filesystem.

## New artifact

`xsmb-quant/verification/render_runtime_evidence.py`

It records only compact metadata:

- action id;
- fixture identity and SHA-256;
- observed peak RSS;
- 320 MB safety guard;
- 512 MB platform hard ceiling;
- elapsed time;
- child exit code;
- status;
- promotion state;
- hashes of stdout/stderr tails.

It deliberately does **not** persist bulk source payloads or historical datasets.

## Required persistence topology

```text
Render bounded runner
        |
        v
compact runtime envelope
        |
        +--> hash
        |
        v
persistent evidence store
        |
        v
Brain index / audit trail
```

## OOM invariant

```text
observed RSS >= 320 MB
        -> DENY
        -> no promotion
        -> route heavy work external
```

512 MB remains a hard platform boundary, not a target.

## Fosennic invariants

- source bytes remain immutable;
- FULL_27 remains canonical truth candidate;
- TAIL_27 is derived only;
- quorum 1/2 remains DENY;
- compact evidence cannot manufacture source truth;
- Render restart cannot erase governance state;
- Layer 1 remains LOCKED;
- staircase remains LOCKED;
- promotion remains DENY.

## Next governed action

Integrate the compact evidence envelope into the deployed runtime's durable evidence path and expose only its metadata through the foundation verification endpoint. Do not expose or persist bulk payloads through Brain/UI.
