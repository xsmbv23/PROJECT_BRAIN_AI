# BRAIN-N104 — Single Forensic FSM Enforcement

## Exact decision

The system MUST keep one Forensic FSM. Database admission states are sequential gates, not independent Forensic systems.

```text
DB_EXISTENCE
 -> DB_BINDING
 -> DB_TLS_ADMISSION
 -> NETWORK_ORIGIN_PROOF
 -> DB_ROUND_TRIP
 -> PROMOTION
```

## Implementation

`core/forensic_gate.py` was upgraded so `NETWORK_ORIGIN_PROOF` is an explicit Gate enum member and an explicit promotion prerequisite.

Promotion now requires independent evidence receipts for all five propositions:

1. DB_EXISTENCE
2. DB_BINDING
3. DB_TLS_ADMISSION
4. NETWORK_ORIGIN_PROOF
5. DB_ROUND_TRIP

The gate module remains pure: no I/O, no network calls, no credentials, no source data.

Added:

`tests/test_forensic_gate_chain.py`

The tests assert:

- earlier PASS does not inherit into a later gate;
- unmet prerequisite causes DENY;
- promotion is denied when network-origin evidence is absent;
- promotion passes only when every required gate has its own receipt.

## Critical doctrine preserved

```text
PASS != AUTHORITY
PASS != PASS(next gate)
UNKNOWN_IS_NOT_PASS
DEFAULT_DENY
NO_INFERENCE_ACROSS_GATES
ONE_FORENSIC_FSM
```

## Data-content separation

Ground Truth validation remains separate from DB admission:

```text
Excel Ground Truth + Web
        -> EXCEL_VS_WEB_GATE
        -> Canonical Data
```

DB admission proves infrastructure/evidence persistence. Ground Truth proves content consistency. Neither substitutes for the other.
