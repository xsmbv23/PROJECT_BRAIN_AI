# BRAIN-N030 — Room Lock / Corridor Isolation

## Architectural correction

The Brain communication model is now explicitly treated as a building of isolated rooms. Every room has its own lock and independent capability. A key for one room cannot open another room.

## Added

`core/corridor_lock.py`

Each `RoomLock` binds:

- room identity;
- layer number;
- unique capability id;
- key fingerprint;
- allowed source corridor/room;
- allowed destination room.

Authorization requires all of these to match.

## Fail-closed rules

```text
wrong capability     -> DENY
wrong key            -> DENY
wrong source         -> DENY
wrong destination    -> DENY
wrong source layer   -> DENY
wrong destination layer -> DENY
```

Possession of a valid key for ROOM_A gives no authority over ROOM_B.

## Layer rule

Layer transitions are explicit. A caller cannot silently jump from a lower/upper layer by reusing a capability issued for another layer.

## Tests

`tests/test_corridor_lock.py` covers:

- valid room entry;
- wrong key;
- cross-room key reuse;
- wrong layer.

## Fosennic invariant

```text
HALL
  ↓ [ROOM_A_KEY only]
ROOM_A

HALL
  ↓ [ROOM_B_KEY only]
ROOM_B
```

No master key exists in the Brain core.
