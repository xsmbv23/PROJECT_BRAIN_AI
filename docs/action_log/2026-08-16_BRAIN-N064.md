# BRAIN-N064 — Immutable Forensic Admission Doctrine Clarification

## Objective

Preserve for successor Bots the exact meaning and interaction of the database admission states.

## Decision

The system has **ONE Forensic FSM**.

Database admission is a monotonic sequence of evidence gates, not multiple independent Forensic state machines.

```text
DB_EXISTENCE
    -> DB_BINDING
    -> DB_TLS_ADMISSION
    -> NETWORK_ORIGIN_PROOF
    -> DB_ROUND_TRIP
    -> PROMOTION
```

The critical rule is:

```text
PASS != AUTHORITY
PASS != PASS(next gate)
UNKNOWN_IS_NOT_PASS
DEFAULT_DENY
NO_INFERENCE_ACROSS_GATES
```

## Important interpretation

`DB_EXISTENCE=PASS` means only that the database resource exists.

It does not mean the Brain service has access.

`DB_BINDING=PASS` means only that an explicit runtime binding exists.

It does not prove TLS admission.

`DB_TLS_ADMISSION=BOUND_TLS` means only that the binding satisfies transport policy.

It does not prove the exact-current network path.

`NETWORK_ORIGIN_PROOF=PROVEN` permits the real durable round-trip test.

`DB_ROUND_TRIP=MATCH` is required before promotion.

## Data-domain separation

Ground Truth validation and DB admission are separate evidence domains inside the same Forensic FSM.

```text
Excel Ground Truth + Web Scraper
             |
       EXCEL_VS_WEB_GATE
             |
       MATCH -> Canonical Data
       DENY  -> HARD DENY

Infrastructure
             |
       DB Admission Chain
             |
       Promotion only after evidence
```

A Ground Truth PASS never proves DB authorization.

A DB Promotion PASS never proves the scraped content is correct.

## Why this was recorded

This prevents a successor Bot from seeing multiple PASS-like states and collapsing them into one unsafe `DATABASE_PASS` boolean.

It also prevents the successor from creating another Forensic FSM merely to represent infrastructure states.

## Immutable successor rule

Before any database admission change, a successor Bot MUST read:

1. `docs/FORENSIC_DATABASE_ADMISSION_CHAIN.md`
2. `state/current_state.json`
3. `state/next_action.json`
4. the newest `docs/action_log/` record

No later gate may be promoted by inference.

