# BRAIN-N080 — Test Governance + Promotion Gate Correction

## Trigger

Exact-current Render deployment `dep-da21b5rl550s73b043lg` reached `LIVE` for commit `d447510ffd9e0902cc81f1e93373cd8e399608c4`.

The boot evidence reported:

- runtime boot gate = PASS
- 82/82 foundation tests = PASS
- DB binding = `BOUND_TLS`
- DB TLS admission = `PASS`
- DB round-trip = `NOT_PROVEN`
- promotion = `ALLOW`

That final combination is an invariant violation.

## Forensic diagnosis

`tools/database_admission.py` already enforced the correct one-FSM rule: a gate PASS is local and only permits evaluation of the next gate. Promotion requires every gate to pass, including `DB_ROUND_TRIP`.

The violation was in `tools/runtime_boot_gate.py`, which independently calculated:

```text
promotion = ALLOW when binding == BOUND_TLS
```

That bypassed the admission FSM and effectively inherited a deeper PASS from a shallower gate.

This was classified as a **CODE VIOLATION**, not a reason to weaken the test suite or admission invariant.

## Correction

`runtime_boot_gate.py` now delegates promotion semantics to the single admission FSM and explicitly treats durable round-trip evidence as false unless independently observed.

Therefore:

```text
BOUND_TLS + NOT_PROVEN_ROUND_TRIP = DENY PROMOTION
```

A new test suite `tests/test_runtime_boot_gate.py` locks this behavior.

## Additional immutable rule

The following is now explicitly preserved:

```text
PASS(gate_n)
    -> permits evaluation of gate(n+1)
    -> never creates PASS(gate(n+1))
```

No runtime shortcut may bypass `DB_ROUND_TRIP`.
