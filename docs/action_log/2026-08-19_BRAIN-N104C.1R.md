## Forensic decision

Do **not** interpret this as an N104C.1 transport failure.
Do **not** interpret it as transport PASS.
Do **not** interpret repository state as runtime proof.
Do **not** infer N104D from chat, old documentation, or unexecuted code.

The governing rule is:

```text
CHAT / BOT CLAIM
      !=
REPOSITORY STATE
      !=
EXACT CURRENT RUNTIME PROOF
```

A milestone becomes authoritative only when its required state, immutable action receipt, and exact-current runtime evidence are mutually consistent.

## Anti-drift upgrade

Added:

```text
 tools/state_drift_detector.py
 tests/test_state_drift_detector.py
```

and made `state_drift` a mandatory `runtime_boot_gate` command.

The detector enforces:

- `current_state.next_action_id == next_action.action_id`
- state mode/action-space alignment
- promotion/layer/staircase alignment
- `pass_inheritance == false`
- `unknown_is_not_pass == true`
- `default_deny == true`
- DATA_ADMISSION cannot regress to bootstrap/foundation state
- a PASS runtime gate must name an explicit verified runtime commit

The detector never auto-fixes state and never upgrades a gate. A mismatch is DENY.

## Action Receipt Validator upgrade

Added a second, independent evidence layer:

```text
 tools/action_receipt_validator.py
 tests/test_action_receipt_validator.py
 docs/forensic/ACTION_RECEIPT_VALIDATOR.md
```

This validator closes the gap between `STATE.last_action` and evidence that the action actually occurred.

The validator requires:

```text
receipt.action_id == state.last_action_id
receipt_sha256 == SHA256(canonical(receipt_without_hash))
receipt.commit_sha == exact_current_runtime.commit_sha
```

It is read-only. It never creates receipts, rewrites state, advances the FSM, or interprets chat intent as evidence.

Therefore the reconciliation chain is now:

```text
STATE
  +
NEXT_ACTION
  +
STATE_DRIFT
  +
ACTION_RECEIPT
  +
RUNTIME_EVIDENCE
        ↓
RECONCILIATION
        ↓
RECONCILIATION_RECEIPT
```

A PASS from `state_drift_detector` does not inherit into `ACTION_RECEIPT_VALIDATOR`.
