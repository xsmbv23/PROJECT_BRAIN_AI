# BRAIN-N104 — Single Forensic FSM Enforcement

## Reason for this action

The architecture discussion clarified a critical invariant: database existence, authorization/binding, security admission, successful round-trip, and promotion are **not separate Forensic systems**. They are guarded propositions inside **one Forensic FSM**.

A PASS from one proposition must never silently become PASS for another proposition.

## Code change

Added:

```text
core/forensic_gate.py
tests/test_forensic_gate.py
```

The module encodes:

```text
DB_EXISTENCE
    -> DB_BINDING
    -> DB_TLS_ADMISSION
    -> DB_ROUND_TRIP
    -> PROMOTION
```

with the invariant:

```text
PASS_IS_LOCAL_TO_GATE
PASS_IS_PREREQUISITE_ONLY
NO_PASS_INHERITANCE
UNKNOWN_IS_NOT_PASS
DEFAULT_DENY
```

Promotion requires independent evidence receipts for every required prior gate.

## Security model preserved

The same semantics apply to physical-style Brain access control:

```text
corridor_key
    + room_key
    + inner_release when protected
```

A corridor key never implies a room key. A room key never implies inner release.

## Current data admission

Source admission remains a separate guarded chain inside the same FSM:

```text
SOURCE_INDEPENDENCE
    -> CANONICAL_QUORUM
    -> TRUTH_ADMISSION
```

Current source independence remains DENY because fresh DNS/RDAP evidence was unavailable. Hostname difference or HTML difference is not accepted as independence proof.

## Current promotion

```text
PROMOTION = DENY
LAYER 1   = ROOM_01_DATA_ADMISSION / controlled
STAIRCASE = LOCKED
```

No Layer 1 expansion is authorized merely because the gate module exists.

## Successor instruction

Future Bots MUST treat `core/forensic_gate.py` and `docs/FORENSIC_GATE_ADMISSION_DOCTRINE.md` as one architectural contract.

Do not create parallel forensic state machines. Do not collapse multiple propositions into one PASS flag. Do not infer downstream PASS from upstream PASS. Every downstream proposition needs its own evidence receipt.
