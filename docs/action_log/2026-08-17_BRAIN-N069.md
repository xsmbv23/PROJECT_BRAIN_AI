# BRAIN-N069 — Bounded Continuous Evidence Loop

## Objective

Preserve the user's N005 hardening proposal without allowing a continuous evidence loop to become an uncontrolled infinite process.

## Permanent semantic target

`N005 = PIPELINE EXECUTION WITH FORENSIC EVIDENCE`

Not:

`N005 = pipeline works`

## Evidence loop

```text
COLLECT(real)
   -> APPEND-ONLY BUFFER
   -> READINESS OBSERVATION
   -> DRY-RUN
   -> ADMISSION CHECK
   -> FORENSIC SNAPSHOT
   -> BOUNDED WAIT
   -> NEXT CYCLE
```

The loop is an **evidence producer**, not an admission bypass.

## Hard invariants

### Readiness is observation only

```text
READINESS_SCORE MUST NOT TRIGGER ADMISSION
```

A high readiness score cannot create a PASS.

### DENY is evidence

Every denied admission attempt remains recorded. A future Bot must never delete or reset prior DENY history merely because a later cycle is cleaner.

### Drift is immutable

```text
DRIFT_DETECTED
    -> DENY
    -> FREEZE OLD RAW SEGMENT
    -> VERSION NEW RAW SEGMENT
```

Never overwrite raw evidence.

### Admission attempts are append-only

Each attempt should contain compact metadata such as:

```text
attempt_id
timestamp
dataset_hash
admission_result
reason
missing_days
conflicts
readiness_score
trace_hash
input_hash
dataset_state_hash
```

No credentials and no bulk source payloads belong in an attempt record.

### Dead pipeline detection

If real collection produces zero new source days for a bounded number of consecutive cycles, emit:

`DEAD_PIPELINE`

Then apply the configured bounded termination/backoff policy.

A process that stays alive while collecting nothing is not a healthy pipeline.

## Anti-infinite-loop guard

Continuous mode MUST have all of:

- `max_cycles` or an equivalent externally enforced cycle budget;
- `max_cycle_seconds`;
- bounded input/data scope per cycle;
- bounded in-memory buffer;
- bounded evidence output size;
- explicit sleep interval;
- dead-pipeline threshold;
- deterministic restart/resume point.

The implementation must never use an unbounded `while True` as the only lifecycle control.

If a long-running service is desired, the outer process supervisor may restart bounded workers. The worker itself remains bounded and forensic-auditable.

## Render OOM protection

Render Free remains a hard 512 MiB environment boundary.

Operational guard remains:

`320 MiB = 335544320 bytes`

Continuous cycles must record compact RSS/peak memory evidence and buffer disk usage. They must not load a growing complete historical dataset into RAM.

If the memory guard is exceeded:

```text
SOFT_DENY
NO_ADMISSION
STOP_OR_BACKOFF_CYCLE
RETAIN_FORENSIC_EVIDENCE
```

Do not attempt to continue by silently raising the guard.

## Forensic admission relation

The loop does not change the database admission chain:

```text
DB_EXISTENCE
 -> DB_BINDING
 -> DB_TLS_ADMISSION
 -> DB_ROUND_TRIP
 -> PROMOTION
```

PASS at one gate remains only a prerequisite to evaluate the next gate.
