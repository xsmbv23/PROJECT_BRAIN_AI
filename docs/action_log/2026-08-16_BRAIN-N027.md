# BRAIN-N027 — Adapter Boundary + Credential Guard

## Assessment

The durable-state abstraction is correct, but the foundation needed an explicit fail-closed guard against credentials accidentally entering Brain source/configuration.

## Implemented

Added `core/credential_guard.py` and `tests/test_credential_guard.py`.

The guard rejects obvious:
- PostgreSQL/Redis connection URLs;
- hard-coded API keys/secrets/passwords/tokens;
- private-key material.

This is a source/config hygiene control, not a substitute for secret-manager controls.

## Architectural boundary

```text
Brain core
  │  metadata only
  ▼
DurableStateStore protocol
  │
  ▼
Runtime adapter
  │  credentials injected externally
  ▼
Single durable authority
```
