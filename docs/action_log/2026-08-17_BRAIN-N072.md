# BRAIN-N072 — Frozen Forensic FSM Handoff

## Decision

The Forensic foundation is frozen. There is **one** ordered Forensic database admission FSM, not two independent Forensic systems.

```text
DB_EXISTENCE
  -> DB_BINDING
  -> SECRET_RESOLUTION
  -> DB_TLS_ADMISSION
  -> NETWORK_ORIGIN_PROOF
  -> DB_ROUND_TRIP
  -> PROMOTION
```

## Immutable invariants

```text
STATE != CAPABILITY != VALIDATION != EXECUTION
PASS IS PREREQUISITE ONLY
NO PASS INHERITANCE
UNKNOWN IS NOT PASS
DEFAULT DENY
FIRST FAIL OR UNKNOWN STOPS REACHABILITY
LATER GATES = UNREACHED
FAILURE HISTORY = APPEND ONLY
NO DERIVED AGGREGATE STATE
```

`DB_EXISTENCE = PASS` does not imply `DB_BINDING`.
`DB_BINDING = PASS` does not imply `SECRET_RESOLUTION`.
`SECRET_RESOLUTION = PASS` does not imply `DB_TLS_ADMISSION`.
`DB_TLS_ADMISSION = PASS` does not imply `NETWORK_ORIGIN_PROOF`.
`NETWORK_ORIGIN_PROOF = PASS` does not imply `DB_ROUND_TRIP`.

Only a real temporal compact-metadata write/read with SHA-256 match can
satisfy the round-trip gate.

## Frozen terminal state

```text
DB_EXISTENCE         = PASS
DB_BINDING           = NOT_BOUND
SECRET_RESOLUTION    = UNREACHED
DB_TLS_ADMISSION     = UNREACHED
NETWORK_ORIGIN_PROOF = UNREACHED
DB_ROUND_TRIP         = UNREACHED
PROMOTION            = DENY
```

This is a truthful terminal state. It is not a defect and must not be turned
into PASS by a workaround, mock, fixture, cache, tunnel, or inferred flag.

## No-derived-state invariant

Never replace the gate-specific FSM with convenience booleans such as:

```text
DATABASE_PASS
DB_READY
DB_OK
DB_AVAILABLE
DB_CONNECTED
```

If a future agent proposes such a value, it must be rejected unless it is an
explicit evidence-bearing gate with its own semantics, provenance, and audit
history.

## Layer boundary

`xsmbv23/Project_Brain_AI` remains the Governance Control Plane.
`xsmbv23/Quant_Engine` is Layer 1.

Quant Engine must not recreate Brain's corridor security, room locks,
permission graph, or Forensic admission FSM. It consumes authorized evidence
and performs computation.

## QUANT-N001

The first Quant execution frame remains intentionally minimal:

```text
CANONICAL REAL DATA
        -> INPUT ADAPTER
        -> ONE SIGNAL/SCORING ROOM
        -> OUTPUT
        -> HASHED EXECUTION RECEIPT
```

No synthetic data. No lookahead. No bulk in-memory data load. No multi-room
orchestration until the first real end-to-end execution is proven.
