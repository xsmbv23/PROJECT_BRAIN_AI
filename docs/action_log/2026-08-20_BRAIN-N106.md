# BRAIN-N106 — Forensic Admission Chain Semantics

There is ONE Forensic FSM, not multiple forensic systems.

```text
ONE FORENSIC FSM
  +-- CURRENT STATE = mutable projection from exact evidence
  +-- HISTORY      = immutable append-only record
```

Gate PASS is local:

```text
PASS_IS_LOCAL
PASS_IS_PREREQUISITE_ONLY
NO_PASS_INHERITANCE
UNKNOWN_IS_NOT_PASS
DEFAULT_DENY
OWN_GATE_EVIDENCE_REQUIRED
```

Therefore:

```text
DB_EXISTENCE=PASS
 != DB_BINDING=PASS
 != DB_TLS_ADMISSION=PASS
 != DB_ROUND_TRIP=PASS
 != PROMOTION=PASS
```

Database admission is one chain inside the same FSM:

```text
DB_EXISTENCE -> DB_BINDING -> DB_TLS_ADMISSION -> DB_ROUND_TRIP -> PROMOTION
```

Each stage requires its own direct evidence. A PASS only permits evaluation of the next stage; it never proves the next stage.

The same rule applies to:

```text
Container Exists != Container Running != Shell Active != Probe Executed != Receipt Proven
```

Strict enforcement:

```text
NO RECEIPT -> NOT_PROVEN -> HARD_DENY
```

Tool silence, repository reachability, database existence, or source inspection cannot substitute for an exact-runtime receipt.
