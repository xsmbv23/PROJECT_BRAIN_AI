## One Forensic FSM

```text

   -> DB_BINDING
      -> DB_TLS_ADMISSION
         -> DB_ROUND_TRIP
            -> PROMOTION
```

These are evidence gates inside the same FSM, not independent Forensic systems.

`PASS` is local to the gate that produced it. It is only a prerequisite for evaluating the next gate and is never inherited.

```text
DB_EXISTS=PASS        != DB_BINDING=PASS
DB_BINDING=PASS       != DB_TLS_ADMISSION=PASS
DB_TLS=PASS           != DB_ROUND_TRIP=PASS
```

## Governed Wait law

```text
NO EVIDENCE
   -> NO TRANSITION
      -> NO ACTION
         -> NO-OP
```

`next_action` is a DAG pointer only. It is never execution authority.

If the current state is `WAIT_EXTERNAL_EVENT`, the pointer is frozen until a genuine external event supplies a Fresh Runtime Receipt.

## Fresh Runtime Receipt admission

For the current phase, transition authority can become non-zero only after a genuine external event and a fresh receipt are observed.

The receipt must prove, without exposing secrets:

1. external provenance;
2. current repository/deployment lineage;
3. freshness for the proposed transition;
4. observable execution evidence (`evidence > 0`);
5. integrity/hash validity;
6. uniqueness / not previously consumed;
7. compatibility with the exact current FSM state.

If any item is unknown, absent, stale, reused, fabricated, or invalid:

```text
DENY / NO-OP
```
