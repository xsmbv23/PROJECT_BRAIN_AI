# BRAIN-N084 — State Artifact Integrity Hardening

## Trigger

A successor-facing report stated that `state/current_state.json` and `state/next_action.json` had been normalized, but exact repository inspection showed both files were still transport envelopes containing `content`, `encoding`, and `sha` fields. This contradiction is itself a Forensic integrity event.

## Correction

The two state files were rewritten as direct JSON artifacts.

`tools/check_state_consistency.py` was hardened so that any transport envelope is a hard failure. It now also requires and verifies:

- `pass_inheritance == false`
- `unknown_is_not_pass == true`
- `default_deny == true`
- `action_space == 0`
- `action == MANDATORY_NO_OP`
- `promotion == DENY` in current state
- `promotion == HARD_DENY` in next-action state
- `layer_1 == LOCKED`
- `staircase == LOCKED`
- current/next action IDs agree

A dedicated regression test file was added:

`tests/test_state_artifact_integrity.py`

## Forensic rule added

A state file is an **artifact**, not a transport response.

```text
VALID STATE
  = direct JSON object
  + required schema
  + semantic invariants
  + pointer consistency
  + no transport envelope
```

If a tool response wraps the artifact in fields such as `content`, `encoding`, or `sha`, that wrapper belongs to the tool transport layer and must never be copied into the repository state artifact.
