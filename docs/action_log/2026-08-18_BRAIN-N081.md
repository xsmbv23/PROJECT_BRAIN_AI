## Second observation

A safe Render Postgres connector query from the control plane also failed with:

```text
FATAL: SSL/TLS required
```

This confirms that the database enforces TLS. The control-plane query surface itself did not provide a TLS-configurable path, so this failure is not treated as evidence that the database is unavailable.

## Forensic interpretation

N081 does NOT prove the durable round-trip.

It DOES prove:

```text
BOUND_TLS observed = YES
TLS admission      = PASS
service-to-DB probe= NOT_PROVEN
write/read/hash    = NOT_PROVEN
promotion          = DENY
```

The failure is most safely classified as a **network/topology/binding resolution problem**, not as permission success/failure, because the service-side adapter intentionally does not expose the underlying connection message or credential-derived data.

The service and database are in different Render regions. Same-region private networking is therefore unavailable. The next action must establish a safe cross-region external TLS binding or deliberately create a same-region replacement topology, without exposing credentials and without pretending either path is proven.

## Safety correction

The first N081 implementation allowed a failed proof to terminate the web process. That was corrected immediately:

```text
proof failure -> evidence + DENY
proof failure -X-> service outage
```

The one-time flag was disabled after the attempt so the normal service returned to its stable foundation runtime.
