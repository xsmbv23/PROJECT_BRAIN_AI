# BRAIN-N065 — Exact-Current Deployment Identity Admission

## Objective

Turn deployment drift into a mandatory Forensic admission condition.

## Implementation

Added:

- `tools/verify_deployment_identity.py`
- `tests/test_deployment_identity.py`
- `contracts/deployment_identity_admission.json`

The gate compares two independently observed identities:

```text
canonical GitHub main commit
          ==
Render deployed commit
```

If either identity is missing, or they differ, the result is `DENY`.

Functional tests cannot override deployment drift.

## Exact evidence

Canonical GitHub `main` observed:

```text
dba4ae89b1508f965bbbb833240af247f85db9e2
```

Render deployment:

```text
dep-da17ps0jo6nc738234b0
commit = dba4ae89b1508f965bbbb833240af247f85db9e2
status = live
```

Therefore the deployment identity gate is:

```text
DEPLOYMENT_IDENTITY = PASS
reason = EXACT_CURRENT_COMMIT
```

## Why this matters

N064 previously exposed a real failure mode: Render could be live while serving an older commit than GitHub `main`.

That state is now explicitly treated as a Forensic admission failure rather than an operational curiosity.

```text
STALE_RENDER + ALL_TESTS_PASS = DENY
```

## Database status remains separate

The deployment identity PASS does not change the database admission state.

```text
DB_EXISTENCE       = PASS
DB_BINDING         = NOT_BOUND
DB_TLS_ADMISSION   = NOT_REACHED
DB_ROUND_TRIP      = NOT_PROVEN
PROMOTION          = DENY
```

This preserves the non-inference law:

```text
PASS_AT_GATE_IS_PREREQUISITE_ONLY
NEVER_INFER_DEEPER_PASS
```

## OOM boundary

No database credentials were exposed or added to GitHub. No bulk dataset was introduced into Brain runtime. The 320 MiB memory guard remains mandatory.
