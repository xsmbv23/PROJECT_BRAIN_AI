# BRAIN-N042 — Two-Key + Protected-Room Verification Boundary

## Implemented

The foundation now has a focused deterministic verifier at `tools/verify_access_path.py`.

It proves, in order:

1. wrong corridor key is denied before room access is considered;
2. correct corridor key + correct room key only creates a protected-room request;
3. request changes the inner latch to `RINGING`, not `RELEASED`;
4. entry cannot be asserted before inside release;
5. only the authorized occupant capability can release the latch;
6. after release, entry can be asserted.

## Canonical state machine

```text
NO_ACCESS
   │
   ├─ bad corridor key ──> DENY
   │
   ▼
CORRIDOR_AUTHENTICATED
   │
   ├─ bad room key ──────> DENY
   │
   ▼
ROOM_REQUEST_AUTHORIZED
   │
   ├─ ordinary room ─────> ENTRY_AUTHORIZED
   │
   └─ protected room
            ↓
         RINGING
            ↓
    AUTHORIZED OCCUPANT
            ↓
         RELEASED
            ↓
          ENTRY
```

## Architectural invariant

A key authenticates a boundary; it never authenticates the next boundary automatically.

```text
corridor_key != room_key != inner_release
```

No master key exists.
