# Forensic Admission Chain — Mandatory Successor Contract

## Core invariant

`PROVISIONED != EXECUTED != CAPTURED != RECORDED != VALIDATED != PROMOTED`

A later state may never be inferred from an earlier state. Every promotion requires evidence generated by the corresponding gate.

## Database admission chain

```text
DB_EXISTS
   |
   v
DB_BINDING
   |
   v
DB_TLS_ADMISSION
   |
   v
DB_ROUND_TRIP
   |
   v
PROMOTION
```

Meaning:

- `DB_EXISTS`: the PostgreSQL resource exists and is observable.
- `DB_BINDING`: the service runtime has an explicit binding named `DATABASE_URL`.
- `DB_TLS_ADMISSION`: the binding is PostgreSQL and uses an accepted TLS mode.
- `DB_ROUND_TRIP`: the service actually writes one compact metadata envelope, reads it back, compares transport evidence, and verifies the expected SHA-256 relationship.
- `PROMOTION`: only after the round-trip evidence is captured and validated may durable DB use be admitted.

## Non-inheritance rule

```text
DB_EXISTS=PASS
    does NOT imply
DB_BINDING=PASS

DB_BINDING=PASS
    does NOT imply
DB_TLS_ADMISSION=PASS

DB_TLS_ADMISSION=PASS
    does NOT imply
DB_ROUND_TRIP=PASS

DB_ROUND_TRIP=PASS
    is the prerequisite for
PROMOTION=PASS
```

## Failure semantics

A failure is forensic evidence, not permission to silently repair the evidence path.

Examples:

```text
DNS_FAIL       -> round_trip = NOT_CAPTURED, reason = DNS_FAIL
TLS_FAIL       -> round_trip = NOT_CAPTURED, reason = TLS_FAIL
TIMEOUT        -> round_trip = NOT_CAPTURED, reason = TIMEOUT
BLOCKED        -> round_trip = NOT_CAPTURED, reason = BLOCKED
NOT_BOUND      -> binding = NOT_BOUND, promotion = DENY
```

Do not retry solely to manufacture a PASS. Any retry must itself be an explicitly logged execution with its own receipt identity.

## Runtime-2 closure

Foundation closure requires a second independent runtime observation:

```text
Runtime-2
  -> EXECUTED
  -> CAPTURED
  -> RECORDED
  -> COMPARED
  -> STOP
```

If Runtime-2 fails, the failure itself is recorded and Foundation remains open. No staircase, Layer 1 promotion, or successor shortcut is permitted.

## OOM invariant

Render Free has a hard 512 MB boundary. Brain runtime retains a 320 MiB guard. Durable work must remain compact and must never load bulk datasets into the Brain process.

## Successor rule

This document is normative. A successor Bot must read it before changing admission state. The chat window is not the source of truth; repository state, action logs, contracts, and runtime receipts are authoritative.
